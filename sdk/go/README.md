# Garrison Go SDK

Go client for the Garrison REST API. The SDK library uses only the standard library; Go 1.21+. The optional interactive console uses golang.org/x/term to hide terminal credentials.

**Garrison Agent Studio.** Garrison is a runtime for headless agent harnesses: a multi-tenant control plane with pull-based workers, exposed over REST, MCP, and A2A. Since 0.2.0 it is also an agent studio built on that runtime, so one platform covers an agentic app from start to finish. You build it with the agent architect (chat) or the canvas, test it in the playground, apply it through an approval, promote it between environments, run and scale it on the workers, and give its end users their own chat at `/apps/{slug}/`. This SDK reaches both halves: the management API for the runtime and the studio, and the end-user gateway of each app.

## Install

There is no tagged release of the Go module yet. Until there is, point your module at your checkout of the repository with a `replace` directive:

```bash
go mod edit -require=github.com/jchristn/Garrison/sdk/go@v0.0.0 -replace=github.com/jchristn/Garrison/sdk/go=/path/to/Garrison/sdk/go
go mod tidy
```

If your machine can fetch `github.com/jchristn/Garrison`, `go get github.com/jchristn/Garrison/sdk/go@main` also works and records a pseudo-version for the current commit.

## Quick start

```go
import garrison "github.com/jchristn/Garrison/sdk/go"

client := garrison.NewClient("http://127.0.0.1:8700")
// The same email and password you use in the dashboard.
if _, err := client.Login(ctx, "admin@garrison", "password", "default"); err != nil {
	return err
}
run, err := client.Agents.Invoke(ctx, "my-agent", garrison.InvokeRequest{Input: "Summarize the release notes", Wait: true, WaitSeconds: 120})
if err != nil {
	return err
}
fmt.Println(run.Status, run.ResultText)
```

Every call takes a `context.Context`.

To sign in with an access key pair instead, call `client.LoginWithKeys(ctx, accessKey, secretKey)`. See "Where the credentials come from" below.

## Where the credentials come from

Email and password sign-in works the same on every runtime: tenant `default`, user `admin@garrison`, and the administrator password. There is no default: on Docker Compose it is `GARRISON_ADMIN_PASSWORD` in `docker/.env`, which `update.sh` generates when it is missing. On Kubernetes it is whatever `GARRISON_ADMIN_PASSWORD` held when `k8s/scripts/generate-secrets.sh` ran, or the random one it printed, stored in Secret `garrison-secrets`. A source build in development mode (`GARRISON_ALLOW_INSECURE_DEFAULTS=true`) uses `password`.

The seeded administrator access and secret keys depend on the runtime:

| Runtime | Access key | Secret key |
|---|---|---|
| Docker Compose | `GARRISON_DEFAULT_ACCESS_KEY` in `docker/.env` (generated by `update.sh`) | `GARRISON_DEFAULT_SECRET_KEY` in `docker/.env` |
| Source build in development mode | `access_garrison_default` | `secret_garrison_default_change_me` |
| Kubernetes (Kustomize or Helm) | random, key `default-access-key` in Secret `garrison-secrets` | random, key `default-secret-key` in Secret `garrison-secrets` |

On Kubernetes, read them with:

```bash
kubectl -n garrison get secret garrison-secrets -o jsonpath='{.data.default-access-key}' | base64 --decode; echo
kubectl -n garrison get secret garrison-secrets -o jsonpath='{.data.default-secret-key}' | base64 --decode; echo
kubectl -n garrison get secret garrison-secrets -o jsonpath='{.data.admin-password}' | base64 --decode; echo
```

You can also create a credential of your own in the dashboard (Access > Credentials); the secret key is shown once.

Responses are dictionaries with the server's camelCase field names, exactly as documented in `REST_API.md`.

## Authentication

`Login`, `LoginWithKeys`, `UseToken`, `UseAccessKey`, `UseSignedRequests` (HMAC-SHA256), and `UseAdminAPIKey`. `TokenDetails` and `Logout` manage the current token.

## Resources

`Tenants`, `Users`, `Credentials`, `Roles`, `Permissions`, `RolePermissions`, `UserRoleAssignments`, `CredentialScopeAssignments`, `Agents`, `Deployments`, `HarnessProfiles`, `PromptTemplates`, `McpServers`, `Secrets`, `WorkspaceTemplates`, `ArtifactStores`, `Nodes`, and `NodePools` provide `List`, `Get`, `Create`, `Update`, `Delete`, and `Action` (for sub-routes such as `rotate` or `cordon`). They decode into whatever you pass as `out`: a typed struct such as `garrison.Agent` or a `map[string]any`. `PromptTemplates` adds typed `Clone`, `Reset`, and `Render` (returning `garrison.PromptTemplate` and `garrison.PromptRenderResponse`); `Pipelines` adds typed `Start` and `Preview` to the same methods; `Triggers` and `NotificationEndpoints` add typed trigger and notification calls (see "Triggers and notifications"); `Agents` adds revision calls, and `Environments` and `Promotions` are typed (see "Agent revisions and promotion"). `Deployments` adds a typed `CompilePreview` (see "Compile preview"). `Manifests`, `Runs`, `Conversations`, `Approvals`, `PipelineRuns`, `PipelineReviews`, `StudioDrafts`, `Analytics`, and `ControlNodes` are fully typed. For anything else, `client.Do(ctx, method, path, query, body, &out)` sends an authenticated request.

Control-plane replicas are read-only: `client.ControlNodes.List(ctx, opts)` returns a `*garrison.ControlNodeList` (a page of `garrison.ControlNode` plus `RespondingNodeID`, the replica that answered) and `client.ControlNodes.Get(ctx, nodeID)` reads one replica. `Status` is one of the `ControlNodeStatus*` constants (`Starting`, `Ready`, `Draining`, `Offline`); `IsLeader` and `LeaderEpoch` (leader only) come from the coordination lease.

## Permission approvals

When a deployment has `ApprovalsEnabled` set (Claude Code profiles, and Codex profiles with CodexAppServer delivery), the harness relays permission prompts to Garrison. The deployment's `ApprovalRules` (`garrison.DeploymentApprovalRule`: `Action`, a `Pattern` in Claude Code rule syntax such as `Bash(git status:*)` or `mcp__github__*`, optional `InputPattern`, and `Description`) decide each request, and `ApprovalDefaultAction` (one of the `ApprovalRuleAction*` constants) covers requests no rule matches. `Ask` sends the request to a person, who has `ApprovalTimeoutSeconds` (10 to 3600, default 300) before `ApprovalTimeoutDecision` applies.

```go
pending, err := client.Approvals.List(ctx, garrison.ApprovalFilter{Status: garrison.ApprovalStatusPending})
decided, err := client.Approvals.Decide(ctx, pending.Objects[0].ID, garrison.ApprovalDecideRequest{
	Decision: garrison.ApprovalDecisionAllow, Reason: "Looks safe", Remember: true,
})
result, err := client.Approvals.Check(ctx, deploymentID, garrison.ApprovalCheckRequest{
	ToolName: "Bash", Input: &garrison.ApprovalToolInput{Command: "git status --short"},
})
```

`Approvals.List` filters by status, run, root run, agent, deployment, decision source, and time range (`FromUTC`, `ToUTC`); for a pending count, use `MaxResults: 1` and read `TotalRecords`. `Approvals.Get` returns an error matching `garrison.IsStatus(err, 404)` for an approval outside the tenant. `Approvals.Decide` fails with 409 (`ApprovalNotPending`) when the approval was already decided, and `Remember` needs Update on the approval's deployment. `Approvals.Check` records nothing and returns a `*garrison.ApprovalCheckResponse`. An `Approval` carries its input as `Input` (a `json.RawMessage` object) when the stored input is a JSON object, and as `InputPreview` text otherwise. `garrison.Run` has `PendingApprovals`, `AwaitingApproval` (the run stays `Running` while it waits), and `ApprovalWaitMs`. The deployment approval fields use `omitempty`: zero values are left out of requests and the server applies its defaults.

## Pipelines

A pipeline runs agents as ordered stages. Each stage gets the caller's input plus the earlier stages' results, rendered by a `PipelineStage` prompt template, and a stage with `RequiresReview` waits for a person before the next stage starts.

```go
var pipeline garrison.Pipeline
err := client.Pipelines.Create(ctx, garrison.Pipeline{Name: "draft-and-edit", Stages: []garrison.PipelineStage{
	{Name: "draft", AgentID: writerID, RequiresReview: true},
	{Name: "edit", AgentID: editorID},
}}, &pipeline)
run, err := client.Pipelines.Start(ctx, pipeline.ID, garrison.PipelineStartRequest{
	Input: "Announce the release", Wait: true, WaitSeconds: 60,
}, "release-announcement-1") // idempotency key, sent as the Idempotency-Key header; "" for none
reviews, err := client.PipelineReviews.List(ctx, garrison.PipelineReviewFilter{
	Status: garrison.PipelineReviewStatusPending, PipelineRunID: run.ID,
})
_, err = client.PipelineReviews.Decide(ctx, reviews.Objects[0].ID, garrison.PipelineReviewDecideRequest{
	Decision: garrison.PipelineReviewDecisionApprove, Comment: "Keep it short",
})
finished, err := client.PipelineRuns.Get(ctx, run.ID, 60) // waits until it ends or waits for a review
```

`Pipelines` takes an identifier or a name for `Get`, `Update`, `Delete`, `Start`, and `Preview`. `Update` advances the pipeline's `Version`; pipeline runs already started keep their snapshot. `Delete` answers 409 (`PipelineInUse`) while pipeline runs are active. `Preview` renders every stage prompt from sample input and sample earlier outputs. Starting needs Execute on the pipeline and on every stage agent; a repeated idempotency key with the same input returns the same pipeline run, and different input answers 409.

`PipelineRuns.List` filters by pipeline, status, caller, and time range. `Get` with `waitSeconds` above 0 (at most 600) waits until the pipeline run ends or waits for a review; the detail carries `Stages`, `Reviews`, and `Runs` (stage run summaries). `Cancel` also cancels the pending review and the current stage run; `Retry` resumes a Failed, TimedOut, or Cancelled pipeline run at the stage where it stopped; `Delete` removes a finished pipeline run (stage runs are kept).

`PipelineReviews.Decide` takes `PipelineReviewDecisionApprove` (the comment reaches the next stage as review notes), `PipelineReviewDecisionRequestChanges` (comment required; the stage runs again with it, at most `MaxRevisions` times, then 409 `RevisionLimitReached`), or `PipelineReviewDecisionReject` (the pipeline run fails). A review that is no longer pending answers 409 (`ReviewNotPending`). Reviews are authorized as approvals (Approval Read and Update). Run tokens cannot use pipelines or reviews.

The pipeline status, outcome, stage status, review status, decision, and decision source values are the `PipelineRunStatus*`, `PipelineRunOutcome*`, `PipelineStageStatus*`, `PipelineReviewStatus*`, `PipelineReviewDecision*`, and `PipelineReviewSource*` constants. Optional `Pipeline` and `PipelineStage` fields use `omitempty`, so zero values take the server defaults: `Active` nil means true, `OutputCharLimit` 0 means 16000, `MaxAttempts` 0 means 1, and `MaxRevisions` nil means 3.

## Triggers and notifications

A trigger starts an agent run or a pipeline run on a cron schedule or when a signed webhook arrives. It runs as the principal that last created or changed it, so creating one needs Execute on its agent (or on the pipeline and every stage agent). A webhook trigger's `SigningSecret` is returned only by `Create` and `RotateSecret`; store it then.

```go
var hook garrison.Trigger
err := client.Triggers.Create(ctx, garrison.Trigger{Name: "on-push", Type: garrison.TriggerTypeWebhook, AgentID: &agentID}, &hook)
fire, err := client.Triggers.DeliverWebhook(ctx, hook.ID, *hook.SigningSecret, []byte(`{"ref":"main"}`), "", "delivery-1")
expression := "0 2 * * *"
var nightly garrison.Trigger
err = client.Triggers.Create(ctx, garrison.Trigger{Name: "nightly", Type: garrison.TriggerTypeCron, AgentID: &agentID, CronExpression: &expression, TimeZone: "America/New_York"}, &nightly)
failed, err := client.Triggers.ListFires(ctx, nightly.ID, garrison.TriggerFireOutcomeFailed, nil)
```

`client.Triggers` adds `List(ctx, opts, triggerType)`, `RotateSecret`, `Fire` (fires now; an optional `TriggerFireRequest.Body` reaches the input template as `webhook.body`), `ListFires`, and `DeliverWebhook` (signs and posts a webhook as an external sender would). Runs a trigger started have `Kind` `Trigger` and `TriggerID`; `RunFilter.TriggerID` lists them, and `PipelineRun.TriggerID` is set the same way.

`client.NotificationEndpoints` manages URLs that receive signed JSON notifications for the `NotificationEvent` constants. It adds `RotateSecret`, `Test` (sends a `Test` notification and returns the delivery after its first attempt), `ListDeliveries` (filter by status), and `GetDelivery`. `NotificationDelivery.Payload` is the notification body as a JSON object (`json.RawMessage`). A loopback or private URL returns an `*garrison.Error` with status 400 and `FieldCodes["url"] == "DestinationBlocked"` unless the operator turned on `Notifications.AllowPrivateDestinations`; link-local addresses such as 169.254.169.254 are always refused.

`garrison.SignWebhook(secret, unixSeconds, body)` builds a signature and `garrison.VerifyWebhook(header, secret, body, tolerance)` checks one (a zero tolerance means 300 seconds). The signature header is `X-Garrison-Signature: t=<unix seconds>,v1=<hex>`, where the hex value is the lowercase HMAC-SHA256, keyed with the UTF-8 bytes of the signing secret, of the timestamp, a period, and the raw body. A header may carry several `v1` values; any match is accepted. The server accepts a webhook only within `Triggers.WebhookToleranceSeconds` (default 300) of its clock, answers every failed check with the same 401 `InvalidSignature`, and returns the earlier fire (HTTP 200, `duplicate` true) for a repeated `X-Garrison-Delivery`. Notifications are signed the same way, so a receiver checks them with the same verify function and ignores a `X-Garrison-Delivery` it has seen before: delivery is at least once.

## Agent revisions and promotion

An agent's content can be saved as revisions. `client.Agents` adds `ListRevisions` (newest first), `SaveDraft` (creates or replaces the single open draft), `GetRevision`, `DeleteRevision`, `PublishRevision`, and `DiffRevisions`; each `AgentRevisionChange` in a diff carries `From` and `To` as `json.RawMessage` (objects for `inputSchema` and `outputSchema`, JSON strings otherwise). A revision argument is an `arv_` identifier or a revision number. `Agent.LatestPublishedRevisionID` and `Agent.DraftRevisionID` are read only.

Each deployment belongs to an `Environment` (default `dev`) and may pin `AgentRevisionID`; an unpinned deployment runs the live agent definition, and `Run.AgentRevisionID` records which revision a run used. `client.Environments.Get` and `Update` read and replace the tenant's ordered environment list (`IsDefault` is true while the default `dev`, `staging`, `prod` order applies).

```go
draft, err := client.Agents.SaveDraft(ctx, agentID, garrison.AgentRevision{Description: "Sharper instructions."})
published, err := client.Agents.PublishRevision(ctx, agentID, draft.ID, "ready for staging")
promotion, err := client.Promotions.Promote(ctx, garrison.PromotionRequest{AgentID: agentID, SourceEnvironment: "dev"})
undo, err := client.Promotions.Rollback(ctx, promotion.ID, "")
```

`Promote` pins the next environment's deployments (or `TargetEnvironment`; `AllowSkip` permits jumping ahead) and returns a `PromotionRecord` with one `PromotionItem` per repinned deployment. `Rollback` restores the previous pins and marks the original record `RolledBack`. `client.Promotions.List(ctx, agentID, appID, opts)` and `Get` read the history.

## Agent assets

An agent asset is a versioned system prompt, skill, reference file, or document template (kind `SystemPrompt`, `Skill`, `ReferenceFile`, or `DocumentTemplate`; a `SystemPrompt` asset requires a prompt template ID). Assets are addressed by ID or name and their versions by number. Uploading a version sends every file base64-encoded; uploading files identical to the current version returns that version instead of creating a new one. Each returned file carries its lowercase hex `sha256`. A revision pins assets through `AgentRevision.AssetPins` (`assetId` plus an optional `version`; no version follows the current one), and deleting an asset a revision pins fails with HTTP 409 and code `AssetInUse`. Upload limits answer 413 (`AssetFileTooLarge`, `AssetVersionTooLarge`, `AssetTooManyFiles`). A run whose pinned file fails its SHA-256 check on the worker ends with outcome `AssetIntegrityFailed`.

```go
asset, err := client.AgentAssets.Create(ctx, garrison.AgentAsset{Name: "release-notes-skill", Kind: garrison.AgentAssetKindSkill})
version, err := client.AgentAssets.UploadVersion(ctx, asset.ID, []garrison.AgentAssetUpload{{Path: "SKILL.md", Content: []byte("# Release notes\n"), MediaType: "text/markdown"}}, "first cut")
data, err := client.AgentAssets.DownloadFile(ctx, asset.ID, version.Number, "SKILL.md")
draft, err := client.Agents.SaveDraft(ctx, "my-agent", garrison.AgentRevision{AssetPins: []garrison.AgentRevisionAssetPin{{AssetID: asset.ID}}})
```

`List(ctx, kind, opts)`, `Get`, `Update`, `Delete`, `ListVersions` (newest first), `GetVersion`, and `UploadRaw` (one file as raw bytes) complete the client. `RunOutcomeAssetIntegrityFailed` names the run outcome.

## Conversation file spaces

Every conversation has a file space: versioned files that all of its turns share. The worker mounts the space into each run's workspace under the deployment's `fileSpaceMountPath` (default `files`), and a run reports the space it used as `fileSpaceId`. `client.FileSpaces` reads and writes the space from outside. Each method takes the owner (`garrison.FileSpaceOwnerConversations` or `garrison.FileSpaceOwnerRuns`) and the conversation or run ID, so you can reach a space from any of its turns.

Writes accept an optional base version. Pass the version you last read (0 for a file that should not exist yet). If someone wrote in between, the server keeps both copies: your content lands under a conflict name, and the result has its conflict flag set and its path set to that name. Leave the base version out to overwrite unconditionally.

```go
owner := garrison.FileSpaceOwnerConversations
zero := 0
result, err := client.FileSpaces.WriteText(ctx, owner, cid, "notes/a.md", "# Notes\n", garrison.FileSpaceWriteOptions{BaseVersion: &zero, MediaType: "text/markdown"})
_, err = client.FileSpaces.WriteBytes(ctx, owner, cid, "data/raw.bin", []byte{0, 1}, garrison.FileSpaceWriteOptions{}) // WriteRaw sends octet-stream
listing, err := client.FileSpaces.List(ctx, owner, cid, false)                   // FileSpaceID, FileCount, TotalBytes, Files
versions, err := client.FileSpaces.Versions(ctx, owner, cid, "notes/a.md")      // newest first
data, err := client.FileSpaces.Read(ctx, owner, cid, "notes/a.md", 0)           // 0 reads the current version
link, err := client.FileSpaces.DownloadURL(ctx, garrison.FileSpaceOwnerRuns, runID, "notes/a.md", 0) // no credentials needed
err = client.FileSpaces.Delete(ctx, owner, cid, "notes/a.md")
```

Errors: 400 `InvalidFilePath`, 404 for an unknown conversation, run, or file, and 413 `FileTooLarge`, `FileSpaceFull`, or `TooManyFiles`. `Run.FileSpaceID` and `Deployment.FileSpaceMountPath` carry the new fields.

## Capability catalog

The capability catalog describes agents, MCP server tools, and harness built-ins the same way, so an orchestrator can choose between them. A `garrison.CapabilityDescriptor` has `ID` (`cap_...`), `Name`, `Kind` (`CapabilityKindAgent`, `CapabilityKindMcpTool`, `CapabilityKindHarnessBuiltIn`), `Origin` (`CapabilityOriginDerived` or `CapabilityOriginManual`), `SourceKey`, the source fields (`SourceAgentID`, `SourceRevisionID`, `SourceMcpServerID`, `SourceToolName`, `SourceHarnessProfileID`, `SourceHarnessType`), `Summary`, `InputSchema` and `OutputSchema` (JSON Schema documents as `json.RawMessage`, nil when none), `Tags`, `Requirements` (node labels a run needs, as `CapabilityRequirement{Key, Value}`), `Hints`, `RefreshWarning`, `LastRefreshedUTC`, `CreatedUTC`, and `LastUpdateUTC`. `TenantID` is nil for descriptors every tenant shares (harness built-ins of built-in profiles).

Derived descriptors follow their source: an agent gets one from its latest published revision, an MCP server one per listed tool, and a harness profile one per entry in `HarnessProfile.ToolProbes`. You cannot change or delete them (409 `CapabilityDerived`). Manual descriptors are yours to create, replace, and delete. Their names are unique per tenant (409 `NameConflict`), and schemas must be JSON Schema (400 with code `InvalidJsonSchema`). `Hints` (`*CapabilityHints`) has `Status` (`CapabilityHintStatusUnknown` until enough runs finish, then `CapabilityHintStatusKnown`), `SampleSize`, `MedianDurationMs`, `P90DurationMs`, `MeanCostUSD`, `WindowDays`, and `ComputedUTC`; the values are nil while the status is Unknown.

```go
agents, err := client.Capabilities.List(ctx, &garrison.CapabilityListOptions{Kind: garrison.CapabilityKindAgent})
billing, err := client.Capabilities.List(ctx, &garrison.CapabilityListOptions{Tag: "billing", Search: "invoice"})
summary := "Find an invoice by number."
schema := json.RawMessage(`{"type":"object","properties":{"number":{"type":"string"}}}`)
created, err := client.Capabilities.Create(ctx, garrison.CapabilityDescriptor{
	Name: "lookup-invoice", Kind: garrison.CapabilityKindMcpTool, Summary: &summary, InputSchema: schema, Tags: []string{"billing"},
})
same, err := client.Capabilities.Get(ctx, "lookup-invoice") // ID or name
updated, err := client.Capabilities.Update(ctx, created.ID, *created)
result, err := client.Capabilities.Refresh(ctx, "") // or Refresh(ctx, mcpServerID)
err = client.Capabilities.Delete(ctx, created.ID)
```

`Refresh` returns a `*CapabilityRefreshResult`: `Agents`, `HarnessBuiltIns`, and `Hints` counts, plus `McpServers`, one `CapabilityServerRefresh` per MCP server with `McpServerID`, `McpServerName`, `Tools`, `Removed`, `Warned`, and `Error` (set when the listing failed). `HarnessProfile.ToolProbes` (`[]HarnessToolProbe`) declares the tools a harness can use when the worker host has them: `Name` (lowercase letters, digits, dots, and hyphens), `Executable` (a bare file name on the worker's PATH), `Arguments` (at most one of `garrison.HarnessToolProbeArguments`, default `--version`), and `Description`. Workers that find the tool report the node label `garrison.io/tool-{name}=true`.

## Fan-out groups

A run fans work out to several agents at once by calling the `garrison_fan_out` MCP tool, then collects the results with `garrison_gather`. The SDK cannot start a group; it reads them and cancels them. A `garrison.FanOutGroup` has `ID` (`fog_...`), `ParentRunID`, `Status` (`FanOutGroupStatusRunning`, `FanOutGroupStatusJoined`, `FanOutGroupStatusTimedOut`, `FanOutGroupStatusBudgetExceeded`, `FanOutGroupStatusCancelled`; every status but Running is final), `StatusReason`, `JoinPolicy` (`FanOutJoinPolicyAll`, `FanOutJoinPolicyAny`, `FanOutJoinPolicyQuorum`), `Quorum`, the counts `Total`, `Finished`, and `Succeeded`, the label lists `Pending` and `Failed`, `Members`, the totals `CostUSD` and `Tokens`, the budget `MaxCostUSD` and `MaxTokens` (nil when unset), `DeadlineUTC`, `CreatedUTC`, and `CompletedUTC`. `Summary`, `ContinuationMarker`, and `ContinuationInstruction` are what a harness sees through `garrison_gather` and are normally nil here.

Each `garrison.FanOutMember` has `Label`, `Agent`, `RunID` (the child run), `Status` (a run status), `Outcome` (nil until it finishes), `ResultText` with `ResultTruncated`, `StructuredOutput` (a `json.RawMessage`, nil when the member produced none), `ErrorMessage`, `FilesWritten` (paths in the shared file space), `CostUSD`, and `Tokens`. A child run's `Run.FanOutGroupID` names its group.

```go
groups, err := client.FanOutGroups.ListByRun(ctx, runID) // oldest first; 404 when the run does not exist
group, err := client.FanOutGroups.Get(ctx, groups[0].ID)
for _, m := range group.Members {
	fmt.Println(m.Label, m.Status, m.RunID)
}
cancelled, err := client.FanOutGroups.Cancel(ctx, group.ID) // cancels members still running
```

A group that does not exist, or belongs to another tenant, is a 404.

## Agentic apps

An agentic app is a group of agents behind one chat UI at `/apps/{slug}/` (see [docs/APPS.md](../../docs/APPS.md)). `client.Apps` lists, reads (by identifier or name), creates, replaces, and deletes them, and adds the delegation plan, app revisions, and promotion. A `garrison.AgenticApp` has `ID` (`app_...`), `Name` (1 to 64 lowercase letters, digits, and hyphens, unique in the tenant), `Slug` (unique across the cluster, default the name; 409 `AppSlugTaken`), `Description`, `EntryAgentID`, `Members` (`AgentID`, `AgentName`, `Role`), `Edges` (`CallerAgentID`, `CalleeAgentID`, `FanOutAllowed`, nil meaning the default true), `Environments` (`Environment`, `DeploymentID`), `LiveEnvironment` (default `dev`), `AuthMode` (`AppAuthModeTenantUsers`, `AppAuthModeAppUsers` (default), `AppAuthModeAnonymous`), `AnonymousEnabled`, `ShowOperatorDetail`, the branding fields `DisplayName` (any characters, up to 128), `LogoAssetID`, `PrimaryColor`, `AccentColor`, `BackgroundColor`, `HeaderColor`, `AgentBubbleColor`, `ConversationListColor`, `ComposerColor`, `FilesColor` (each `#RRGGBB` or nil; anything else is 400 `InvalidColor`), `FontFamily` (`AppFontSystem` (default), `AppFontSans`, `AppFontSerif`, `AppFontRounded`, `AppFontMono`), `FaviconAssetID` (an image asset for the browser tab icon; nil uses the logo; an unknown asset is 400 `UnknownAsset`), and `WelcomeText`, and `LatestPublishedRevisionID`. Agents may be given by name on create and update. The server checks that the entry agent is a member, edges connect members, every member is reachable from the entry agent, and the edges have no cycle. An agent in an app cannot be deleted (409 `AgentInUse`).

```go
app, err := client.Apps.Create(ctx, garrison.AgenticApp{
	Name: "research", EntryAgentID: "orchestrator",
	Members: []garrison.AgenticAppMember{{AgentID: "orchestrator"}, {AgentID: "researcher"}},
	Edges:   []garrison.AgenticAppEdge{{CallerAgentID: "orchestrator", CalleeAgentID: "researcher"}},
})
plan, err := client.Apps.Delegation(ctx, app.ID)         // Drift marks members whose published policy differs
applied, err := client.Apps.ApplyDelegation(ctx, app.ID) // writes drafts; nothing is published
draft, err := client.Apps.CreateRevision(ctx, app.ID, "first cut")
published, err := client.Apps.PublishRevision(ctx, app.ID, strconv.Itoa(draft.Number))
record, err := client.Apps.Promote(ctx, app.ID, garrison.AppPromotionRequest{SourceEnvironment: "dev"})
```

Each `garrison.AppDelegationMember` has the graph's `DesiredMode` (`AllowList`, or `None` for a member that calls nobody), `DesiredAllowList`, and `DesiredMaxDepth`, the latest published revision's `PublishedMode`, `PublishedAllowList`, and `PublishedMaxDepth`, `Drift`, and after an apply `DraftRevisionNumber` or `SkippedReason` (`DraftConflict` when the member's open draft already changes its delegation another way). `CreateRevision` pins every member's latest published revision (409 `NoPublishedRevision` when a member has none); `Revisions` lists them newest first and `GetRevision` reads one by identifier (`apv_...`) or number. `Promote` returns a `PromotionRecord`: every member's pin moves to every deployment of that member in the target environment together (409 `NoTargetDeployments` names a member without one); roll it back with `client.Promotions.Rollback`. Promotion needs Execute on `Promotion` for the target environment.

`garrison.ResourceTypeAgenticApp` names apps in permissions, and `garrison.AppUserRole` (`AppUser`) is the built-in role that lets a user use one app's chat UI when assigned with resource scope on the app identifier. `Conversation.AppID` names the app whose chat UI started a conversation.

## Studio drafts

A studio draft holds manifest documents, one per resource, that a person or the agent architect edits before anything changes in live configuration (see [docs/STUDIO.md](../../docs/STUDIO.md)). `client.StudioDrafts` lists (`List(ctx, mine, opts)`, where `mine` keeps only your own and `opts.Search` matches the title), creates (`Create(ctx, title, fromApp)`; a non-empty `fromApp` starts from an existing app and everything it references), reads, and deletes drafts. A `garrison.StudioDraft` has `ID` (`sdr_...`), `Title`, `OwnerUserID`, `OwnerName`, `TargetApp`, `Version`, `Status` (`StudioDraftStatusOpen`, `StudioDraftStatusPendingApproval`, `StudioDraftStatusApplied`, `StudioDraftStatusDiscarded`), `ApprovalID`, `PublishOnApply`, `ManifestApplyID`, `Items` (`Kind`, `Name`, `Operation`, `Document`, `BaseHash`), and `Layout`.

Every change names the draft version you read. When someone else changed the draft first, the call fails with 409 `DraftVersionConflict` and changes nothing, so read it again and retry. Only an `Open` draft changes (409 `DraftNotOpen`).

```go
draft, err := client.StudioDrafts.Create(ctx, "research app", "")
doc := "apiVersion: garrison/v1\nkind: Agent\nmetadata:\n  name: researcher\nspec:\n  displayName: Researcher\n"
draft, err = client.StudioDrafts.PutItem(ctx, draft.ID, "Agent", "researcher", draft.Version, doc, garrison.StudioDraftOperationUpsert)
graph, err := client.StudioDrafts.GraphOperation(ctx, draft.ID, garrison.StudioGraphOperationRequest{
	Version: draft.Version, Operation: garrison.StudioGraphOperationAddMember, App: "research", Agent: "researcher",
})
diff, err := client.StudioDrafts.Diff(ctx, draft.ID) // Validate returns the same shape
approval, err := client.StudioDrafts.RequestApply(ctx, draft.ID, graph.Version)
_, err = client.Approvals.Decide(ctx, approval.ID, garrison.ApprovalDecideRequest{Decision: garrison.ApprovalDecisionAllow})
```

`PutItem` takes the operation (`StudioDraftOperationUpsert`, or `StudioDraftOperationDelete` for `Agent`, `Deployment`, `Pipeline`, and `AgenticApp`; empty means Upsert) and one manifest document whose kind and name match the item. `RemoveItem(ctx, id, kind, name, version)` drops an item. `Diff` and `Validate` return a `garrison.StudioDraftDiff`: `Valid` (nothing failed and nothing is stale) and one `StudioDraftDiffItem` per item with `Change` (`Create`, `Update`, `Delete`, `Unchanged`, or `Failed`), `Changes` (`ManifestFieldChange`), `Message`, `ErrorCode`, and `Stale`.

`Graph` returns a `garrison.StudioGraph` with `Nodes` (`Key`, `Kind`, `Name`, `InDraft`, `Deleted`, `EntryOf`, `MemberOf`, `Capabilities`, `X`, `Y`) and `Edges` (`App`, `From`, `To`, `FanOut`, `Depth`). `Capabilities` lists, for an agent the draft holds, the capabilities its document names (host tools such as pandoc), and `Depth` is the delegation depth an edge needs: one plus the longest chain of calls below the called member. `GraphOperation` changes it one step at a time with a `StudioGraphOperationRequest`: `StudioGraphOperationAddMember` (`Agent`, optional `Role`; the first member becomes the entry agent), `RemoveMember`, `Connect` (`From`, `To`, optional `FanOut`), `Disconnect`, `SetEntry`, and `MoveNode` (`NodeKey`, `X`, `Y`). `App` defaults to the draft's target app.

`RequestApply` validates the draft (400 `DraftStale`, `DraftInvalid`, or `DraftEmpty`), returns an `Approval` with `Kind` `ApprovalKindDraftApply` and `DraftID` set, and moves the draft to `PendingApproval`. Nothing changes until a person decides the approval through `client.Approvals.Decide`: Allow needs Create on `Manifest` (403 `ApproverLacksPermission`) and answers 409 `DraftStale` when live configuration moved since the request; Deny returns the draft to `Open`. `garrison.ResourceTypeStudioDraft` names drafts in permissions.

## Agent architects

Every tenant has a protected agent named `agent-architect` that designs agents and apps in a draft. An agent architect is a deployment of it, or any deployment with `ManagementAccess` `ManagementAccessDrafts`, which lets its runs edit drafts for the person talking to it, never apply them. `client.StudioDrafts` manages architects directly, so you never build the deployment yourself:

```go
model := "claude-sonnet-4-5"
architect, err := client.StudioDrafts.CreateArchitect(ctx, garrison.ArchitectRequest{
	Name: "architect", HarnessProfileID: "hrn_builtin_claude_code", Model: &model,
}) // a nil ArchitectPromptTemplateID binds builtin/agent-architect
page, err := client.StudioDrafts.Architects(ctx, &garrison.ListOptions{MaxResults: 10, Search: "arch", ActiveOnly: true})
read, err := client.StudioDrafts.Architect(ctx, "architect") // identifier or name
guided := "builtin/agent-architect-guided"
inactive := false
architect, err = client.StudioDrafts.UpdateArchitect(ctx, architect.ID, garrison.ArchitectRequest{
	Name: "architect", HarnessProfileID: "hrn_builtin_claude_code", Active: &inactive, ArchitectPromptTemplateID: &guided,
})
err = client.StudioDrafts.DeleteArchitect(ctx, architect.ID) // drafts are kept
```

A `garrison.Architect` has `ID` (the deployment identifier), `TenantID`, `Name`, `Description`, `AgentID`, `AgentName`, `HarnessProfileID`, `Model`, `Active`, `ArchitectPromptTemplateID`, `ArchitectPromptName`, `ArchitectPromptVersion` (nil follows the template's current version), `ArchitectPromptCurrentVersion`, `ConfigVersion`, `IsProtected`, `CreatedUTC`, and `LastUpdateUTC`. A `garrison.ArchitectRequest` takes `Name` and `HarnessProfileID` (both required; 400 without them), `Description`, `Model`, `Active`, `ArchitectPromptTemplateID`, and `ArchitectPromptVersion` (1 or more, or nil). A nil `Active` creates an active architect; on update, pass a pointer to false to turn it off. On update, a nil `ArchitectPromptTemplateID` keeps the current prompt, and deployment settings the request does not name are kept. `CreateArchitect` fails with 409 `NameConflict` for a name in use and 409 `ArchitectAgentMissing` when the tenant has no `agent-architect`; create and update fail with 400 `InvalidArchitectPrompt` for a template that is not a readable `System` template. `Architect`, `UpdateArchitect`, and `DeleteArchitect` fail with 404 for a deployment that is not an architect. `Architects` returns an `EnumerationResult[Architect]` and honors `ListOptions` `MaxResults` (1 to 1000, default 25), `Skip`, `Ordering`, `Search` (part of the name), and `ActiveOnly`. These calls need Read, Create, Update, or Delete on `Deployment`. An `Architect` also carries `CredentialSecretID`, `CredentialSecretName`, and `CredentialSecretKind` (all nil when none is bound). `ArchitectRequest.CredentialSecretID` takes the identifier or name of an active tenant secret that the harness signs in with, bound to the deployment under the alias `credential` (400 `InvalidCredentialSecret` otherwise); nil is not sent, so it binds none on create and keeps the current one on update, and a pointer to an empty string on update removes it. `Deployment.ArchitectPromptTemplateID` and `ArchitectPromptVersion` are still accepted when `Deployments.Create` creates a deployment of `agent-architect`.

## Architect prompts

An architect's System prompt is chosen per deployment (see [docs/PROMPTS.md](../../docs/PROMPTS.md#architect-prompts)).

```go
prompts, err := client.StudioDrafts.ArchitectPrompts(ctx, &garrison.ListOptions{MaxResults: 50}) // built-ins first, then clones, then other System templates
clone, err := client.PromptTemplates.Clone(ctx, prompts.Objects[0].ID, "my-architect")
selection, err := client.StudioDrafts.SetArchitectPrompt(ctx, architect.ID, clone.ID, nil) // nil follows the current version
selection, err = client.StudioDrafts.ArchitectPrompt(ctx, architect.ID)
reset, err := client.PromptTemplates.Reset(ctx, clone.ID) // back to the shipped text, as a new version
```

`ArchitectPrompts` returns one page, an `EnumerationResult[ArchitectPromptEntry]`. The order is fixed, so `Ordering` does not apply; `MaxResults`, `Skip`, and `Search` (part of the name) do, and opts may be nil. Each `garrison.ArchitectPromptEntry` has `ID`, `Name`, `Description`, `IsBuiltIn`, `BuiltInKey`, `CurrentVersion`, `IsDefault`, and `Deployments` (the architect deployments that use it). A `garrison.ArchitectPromptSelection` has `DeploymentID`, `ArchitectPromptTemplateID`, `ArchitectPromptName`, `ArchitectPromptVersion` (nil when it follows the current version), and `CurrentVersion`. The template is given by identifier or name. Setting a prompt on a deployment that is not an architect fails with 400 `NotAnArchitectDeployment`, and a template that is not a readable `System` template with 400 `InvalidArchitectPrompt`. A template that any deployment binds cannot be deleted (409 `PromptTemplateInUse`).

## Playground

The studio playground runs an agent's draft revision before anything is published (see [docs/STUDIO.md](../../docs/STUDIO.md#playground)). Each run goes to a temporary copy of one of the agent's deployments (its `dev` deployment, or the first one) in the reserved environment `garrison.PlaygroundEnvironment` (`draft`), pinned to the revision being tried. Playground runs have `Kind` `garrison.RunKindPlayground` and set `AgentRevisionID`.

```go
draft, err := client.Agents.SaveDraft(ctx, "researcher", garrison.AgentRevision{Description: "Tighter scope."})
run, err := client.Agents.PlaygroundInvoke(ctx, "researcher", garrison.PlaygroundInvokeRequest{
	Input: "Summarize the release notes", AgentRevisionID: draft.ID, WaitSeconds: 60,
})
// Try a studio draft: its document for Agent (default the target app's entry agent) becomes the agent's draft revision.
run, err = client.StudioDrafts.PlaygroundInvoke(ctx, studioDraftID, garrison.PlaygroundInvokeRequest{
	Input: "Summarize the release notes", Agent: "researcher",
})
```

`garrison.PlaygroundInvokeRequest` has `Input`, `Agent` (studio draft route only), `AgentRevisionID` (agent route only; empty runs the open draft, or the latest published revision when there is none), `SourceDeploymentID` (agent route only; empty uses the agent's `dev` deployment, else its first), `ConversationID`, `Wait` (nil means true), and `WaitSeconds` (0 means the server default of 120; clamped to 1 through 3600). The agent route needs Execute on `Agent`. The studio draft route writes the draft's document as the agent's draft revision and runs it without changing live configuration; it needs Update on `StudioDraft` and on `AgentRevision`, and fails with 400 `AgentNotLive` for an agent the draft creates. An agent with no deployment to copy fails with 400 `NoDeployment`. `Run.Kind` takes the `RunKind*` constants.

## Compile preview

`client.Deployments` is a `*garrison.DeploymentsClient`: the generic resource methods plus `CompilePreview(ctx, id, req)`, which compiles a deployment with sample input and returns a `*garrison.CompilePreviewResponse` with `Spec` and `TemplateVersions` (raw JSON), `CommandLine`, `DeploymentID`, and `AgentRevisionID`. Secret values are redacted. `garrison.CompilePreviewRequest` takes `Input`, `Parameters`, and two studio options:

- `AgentRevisionID` compiles with another revision of the agent, such as a draft before it is published. It also needs Read on `AgentRevision`.
- `Environment` compiles the same agent's deployment in that environment instead (400 `NoDeploymentInEnvironment` when there is none).

```go
preview, err := client.Deployments.CompilePreview(ctx, devDeploymentID, garrison.CompilePreviewRequest{
	Input: "Preview the draft", AgentRevisionID: draft.ID,
})
fmt.Println(preview.DeploymentID, *preview.AgentRevisionID, preview.CommandLine)
```

`DeploymentID` is the deployment that was compiled (another one when `Environment` was set) and `AgentRevisionID` the revision used (nil when the agent has no revisions).

## Conversations

A conversation is a multi-turn session with one agent. Each turn is a run, and every turn after the first resumes the harness session the earlier turns built, on the node that holds that session's directories. Set `StartConversation: true` on an `InvokeRequest` or `RunCreateRequest` to start one; the returned run's `ConversationID` names it. Set `ConversationID` to send the next turn. Deployment tests take the same body: `client.Deployments.Action(ctx, id, "test", garrison.InvokeRequest{...}, &run)`.

```go
first, err := client.Agents.Invoke(ctx, "my-agent", garrison.InvokeRequest{Input: "Plan the migration", Wait: true, StartConversation: true})
conversationID := *first.ConversationID

second, err := client.Agents.Invoke(ctx, "my-agent", garrison.InvokeRequest{Input: "Now write step 1", Wait: true, ConversationID: conversationID})
fmt.Println(second.ConversationTurn, second.ResultText) // 2 ...

conversation, err := client.Conversations.Get(ctx, conversationID)
turns, err := client.Conversations.ListRuns(ctx, conversationID, 0, 0) // oldest first
err = client.Conversations.Delete(ctx, conversationID)                // the runs are kept
```

Turns of one conversation never overlap. A turn sent while the previous one is unfinished is refused, not queued, with HTTP 409 and code `ConversationBusy`; wait for the previous run (or cancel it) and send again:

```go
_, err := client.Agents.Invoke(ctx, "my-agent", garrison.InvokeRequest{Input: "Next", Wait: true, ConversationID: conversationID})
var apiErr *garrison.Error
if errors.As(err, &apiErr) && apiErr.StatusCode == 409 && apiErr.Code == "ConversationBusy" {
	if c, err := client.Conversations.Get(ctx, conversationID); err == nil && c.ActiveRunID != nil {
		_, _ = client.Runs.WaitForCompletion(ctx, *c.ActiveRunID)
	}
}
```

Other 409 codes are `ConversationAgentMismatch` (the conversation belongs to another agent), `ConversationDeploymentMismatch` (the request names a deployment other than the conversation's), and `ConversationDeploymentUnavailable` (the conversation's deployment was deleted). An unknown `ConversationID` returns 404. `Conversations.Delete` also returns 409 `ConversationBusy` while a turn is unfinished.

`Conversations.List(ctx, garrison.ConversationFilter{...})` filters by `AgentID`, `ContextID` (the A2A context the conversation was created for), `CallerID`, and `Search`, with `Ordering`, `MaxResults`, and `Skip`. `RunFilter.ConversationID` lists a conversation's runs through `Runs.List`. A `garrison.Conversation` carries `TurnCount`, `SessionID`, `AffinityNodeID` and `AffinityNodeName`, `ActiveRunID`, `LastRunID`, `Busy` (true while a turn is unfinished), `FallbackCount`, and `LastFallbackReason`.

Each turn's `Run` has `ConversationID` (`*string`), `ConversationTurn` (`int`: 1 for the first turn, 0 outside a conversation), `ResumeSessionID`, `AffinityNodeID`, `AffinityUntilUTC`, and `ConversationFallbackReason`. A fallback happens when the turn cannot resume and starts a fresh session seeded with the transcript of the earlier turns instead; the `ConversationFallback*` constants list the values (`AffinityNodeLost`, `AffinityWaitExpired`, `WorkspaceLost`, `SessionMissing`, `HarnessChanged`, `ResumeUnsupported`, `ExecutorWithoutState`). A turn that could not even fall back ends with `RunOutcomeConversationStateLost`. See "Conversations" in `REST_API.md`.

## Run timing and usage fields

`garrison.Run` carries timing and usage measurements. Pointer fields are nil when the server could not measure them (the server omits most of them from JSON, and sends `outputTokensPerSecond` as `null`):

- `FirstTokenUTC`, `LastTokenUTC` (`*string`): ISO 8601 UTC times of the first and last model output event.
- `TimeToFirstTokenMs`, `StreamingMs`, `ExecutionMs`, `QueueMs`, `TotalMs` (`*int64`): durations in milliseconds.
- `DelegationWaitMs` (`*int64`): time the run spent waiting on child runs it started (delegation), measured from server timestamps of the runs whose `parentRunId` is this run.
- `TimeToFirstTokenExcludingDelegationMs` (`*int64`): `TimeToFirstTokenMs` minus the delegation wait that happened before the first token; never negative.
- `OutputTokensPerSecond` (`*float64`): nil when there was no streaming window or it was shorter than 100 ms.
- `ReasoningTokens`, `ToolCallCount` (`int64`, default 0), alongside `InputTokens`, `OutputTokens`, `CachedTokens`, and `CostUSD`.

`Run.BlockedReason` (`*string`) is computed by the server when a run is read. It is nil unless the run is `Queued` and no Ready worker can run it. Values: `NoReadyWorker` (no node is Ready), `NoCapableWorker` (no Ready node reports the run's harness), `NoMatchingPool` (capable nodes exist but none matches the deployment's node pool or node selector), `NoIsolatingWorker` (the run is `Untrusted` or its deployment has an egress allowlist, and no Ready node with its harness can isolate it or enforce the allowlist), `NoToolWorker` (the run's agent uses a harness built-in capability such as pandoc, and no Ready worker that can run it reports that tool). The tenant overview counts these runs as `blockedRuns`. See "Blocked runs" in `REST_API.md`.

Runs stopped by a worker run guard end `Failed` with outcome `RunOutcomeRepetitionDetected` (the assistant text degenerated into a short repeated unit or into text with no letters or digits), `RunOutcomeOutputLimitExceeded` (more assistant text than the deployment's `maxAssistantChars`), or `RunOutcomeNoProgress` (nothing happened for `noProgressSeconds`). The partial output is in `Run.ResultText`, and the run has one `Warning` event with code `RunGuardTriggered`. A waiting invoke cancels its run when the connection drops (for example when its `context.Context` is cancelled); set `InvokeRequest.CancelOnDisconnect` to a pointer to `false` to keep the run going. See "Run guards" and "Cancellation" in `REST_API.md`.

When the agent has an output schema, the server validates each run's final output against it. `Run.OutputSchemaValid` (`*bool`) is set after validation and nil when nothing was validated, `Run.SchemaValidationErrors` (`*string`) holds the first few errors of a failed validation, and `Run.RepairAttempts` (`int`, 0 or 1) counts the structured output repair Garrison makes when the harness can resume its session. A run whose output still does not validate fails with outcome `RunOutcomeSchemaValidationFailed`; the `RunOutcome*` constants list every outcome. See "Structured output validation" in `REST_API.md`.

## Executors and run pods

`Node.Containerized` is true when the worker reported at registration that it runs inside a container or pod (`GARRISON_WORKER_CONTAINERIZED`); the built-in Codex profiles then default their sandbox to `danger-full-access`, and a deployment `sandbox` parameter still wins. Default false.

`Deployment.Executor` is `RunExecutorProcess` (the default) or `RunExecutorKubernetesJob` (a Kubernetes Job per run); nil uses the node pool's `NodePool.DefaultExecutor`, then Process. `Deployment.PodResources` (`RunPodResources`) sets the run pod's requests and limits as Kubernetes quantities. `Run.Executor` records the executor, `Node.Executors` lists what a worker can run, and only nodes reporting a run's executor claim it. `WorkspaceKindPersistentVolume` with `WorkspaceTemplate.PersistentVolumeClaim` mounts an existing claim at the workspace path (KubernetesJob runs only). `RunOutcomePodFailed` marks run pods that failed outside the harness. See `docs/KUBERNETES.md`.

## Secret status

The control plane refreshes ChatGPT logins stored in `CodexAuthJson` secrets itself, shortly before the access token expires, and writes the rotated tokens back to the secret. When OpenAI rejects the stored refresh token for good (reused, expired, or revoked), the secret's status becomes `NeedsReauthentication`.

Decode secrets into `garrison.Secret`: `Status` (`SecretStatusOk` or `SecretStatusNeedsReauthentication`), `StatusMessage` (the provider error, empty when `Ok`), `StatusUTC` (when the status left `Ok`), `RefreshedUTC` (when the control plane last refreshed the login itself), and `AccessTokenExpiresUTC` (expiry of the stored access token; `CodexAuthJson` only). To find secrets that need attention, list them into `garrison.EnumerationResult[garrison.Secret]` and check `Status == garrison.SecretStatusNeedsReauthentication`, then set a new value with `client.Secrets.Action(ctx, id, "rotate", map[string]string{"value": newAuthJSON}, nil)`. A run whose deployment binds a secret in that state fails before it starts, with outcome `NotCredentialed` and an error message that starts with `SecretNeedsReauthentication:`. (`SecretRefreshFailed:` means the access token was expired and the refresh failed for a passing reason such as a network error; the secret stays `Ok` and a retry may work.) The fix is to replace the value: sign in again with `codex login` using a `CODEX_HOME` nothing else uses, then set the new `auth.json` as the secret's value. Setting a value returns the status to `Ok`. Do not keep using that login on another machine, because both copies share one refresh token; for shared deployments an `OpenAiApiKey` secret is simpler. See "Codex logins" in `docs/SECURITY.md`.

## Run analytics

`client.Analytics.Runs(ctx, garrison.AnalyticsQuery{...})` calls `GET /v1.0/api/tenants/{tenantId}/analytics/runs` and returns a `*garrison.RunAnalytics` with `Totals` and one or more `Series`, each holding time `Buckets` (`StartUTC` plus the same metrics as `Totals`). Query fields are optional: `From` and `To` (ISO 8601 UTC), `Interval` (`minute`, `hour`, `day`, `week`, or `auto`), `AgentID`, `HarnessType`, `DeploymentID`, `Model` (served model; `unknown` matches runs without a recorded model), and `GroupBy` (`none`, `agent`, `harness`, `model`, or `harnessModel`). With `harnessModel` each series key is `Harness|model` (for example `ClaudeCode|claude-sonnet-5-5`) and its label is `Harness / model`. `BucketSeconds` in the response is the authoritative bucket size. `AnalyticsMetrics` includes `TimeToFirstTokenExcludingDelegationMsAvg`, `TimeToFirstTokenExcludingDelegationMsP50`, `TimeToFirstTokenExcludingDelegationMsP95`, and `DelegationWaitMsAvg` (all `*float64`, nil without samples), so agents that delegate can be compared with agents that answer directly.

```go
now := time.Now().UTC()
stats, err := client.Analytics.Runs(ctx, garrison.AnalyticsQuery{
	From:     now.Add(-24 * time.Hour).Format(time.RFC3339),
	To:       now.Format(time.RFC3339),
	Interval: "hour",
	GroupBy:  "agent",
})
if err != nil {
	return err
}
fmt.Println(stats.Totals.Runs, stats.Totals.CostUSD)
for _, series := range stats.Series {
	fmt.Println(series.Label, len(series.Buckets))
}
```

The server returns HTTP 400 when `From` is not before `To`, when the range needs more than 400 buckets, or for an invalid interval, group, harness type, or date.

`client.Analytics.Dimensions(ctx, from, to)` calls `GET /v1.0/api/tenants/{tenantId}/analytics/runs/dimensions` and returns a `*garrison.AnalyticsDimensions` listing the distinct `Agents` (`ID`, `Name`), `Harnesses`, `Deployments` (`ID`, `Name`, `AgentID`), and `Models` among runs in the range, plus `Truncated`. Pass empty strings for the server default range (the last 24 hours). Use it to fill filter pickers, then feed a value back into `AnalyticsQuery`:

```go
dims, err := client.Analytics.Dimensions(ctx, now.Add(-7*24*time.Hour).Format(time.RFC3339), now.Format(time.RFC3339))
if err != nil {
	return err
}
for _, model := range dims.Models {
	byModel, err := client.Analytics.Runs(ctx, garrison.AnalyticsQuery{Model: model, GroupBy: "harnessModel"})
	if err != nil {
		return err
	}
	fmt.Println(model, byModel.Totals.Runs)
}
```

## Manifests

```go
result, err := client.Manifests.Apply(ctx, yamlText, true, false) // dry run
if err != nil {
	return err
}
items, err := result.ParsedItems()
if err != nil {
	return err
}
for _, item := range items {
	fmt.Println(item.Kind, item.Name, item.Result, item.Message)
	for _, change := range item.Changes {
		fmt.Println("  ", change.Field, change.Before, change.After)
	}
}
```

Each `ManifestApplyItem` reports what the apply did, or for a dry run what it would do. Items that are (or would be) `Updated` carry `Changes` (`ManifestFieldChange`: `Field`, `Before`, `After`; `Before` and `After` are `*string`), with values truncated to 200 characters. `Warnings` lists values in the document that were accepted but not stored as written; see "Warnings".

`Manifests.Export` returns a multi-document YAML bundle that apply accepts unchanged (`GET .../manifests/export`). With no selectors it exports every tenant-owned resource. `ManifestExportOptions.Kinds` names whole kinds, `Resources` names single records as `Kind/name` (split on the first `/`), `FollowReferences` also exports what the selection depends on (an agent brings its deployments, the triggers and notification endpoints that target it, and agents it may delegate to; a deployment brings its agent, harness profile, prompt templates, workspace template, and MCP servers; a pipeline brings its stage agents, pinned deployments, handoff templates, and triggers), and `IncludeBuiltIn` adds referenced built-in prompt templates and harness profiles. Secret values are never exported: the first document is a `kind: Bundle` document listing `requiredSecrets`, `requiredArtifactStores`, and `requiredBuiltIns`, and applying it to a tenant that lacks one fails with `errorCode` `MissingSecret`, `MissingArtifactStore`, or `MissingBuiltIn`. A reference that cannot be resolved fails with `MissingSecret` or `ReferenceNotFound` and an `errorField` naming it. Re-applying an applied bundle reports every document `Unchanged`. An unknown kind is a 400 with field code `UnknownKind`, a malformed resource selector is a 400 with `InvalidSelector`, and a selected resource that does not exist is a 404.

```go
bundle, err := client.Manifests.Export(ctx, garrison.ManifestExportOptions{Resources: []string{"Agent/triage"}, FollowReferences: true})
```

## Transcripts

```go
markdown, err := client.Runs.TranscriptMarkdown(ctx, runID, false)
transcript, err := client.Runs.Transcript(ctx, runID, true) // include thinking
conversation, err := client.Conversations.Transcript(ctx, conversationID, false)
```

A transcript covers one run, or every turn of a conversation oldest first (`GET .../runs/{id}/transcript` and `GET .../conversations/{id}/transcript`). The Markdown form is for reading and sharing; the JSON form is the typed `Transcript` document (schema `garrison.transcript/v1`): `kind` (`Run` or `Conversation`), `turnCount`, total `usage`, and `turns`, each with the redacted `input`, `entries` (assistant text, tool calls and results, warnings, errors, lifecycle notes; thinking only when requested), `approvals`, `result`, `errorMessage`, `usage` (tokens, tool calls, cost, duration), and timestamps. Secrets read `[REDACTED]`, tool text is cut to the server's `Transcripts.ToolTextMaxChars` (`textTruncated`), and a transcript over `Transcripts.MaxBytes` is cut with `truncated` and a `truncationNote`. Unknown or other-tenant identifiers are a 404.

## Structured input

An agent with `inputSchema` (a JSON Schema document, sent as a JSON object) only accepts input that is a JSON document matching it, on every surface. Saving a schema that is not valid JSON Schema fails with field code `InvalidJsonSchema`. An invocation whose input is not JSON is a 400 with field code `InputNotJson` on `input`; one that breaks the schema is a 400 with `InputSchemaViolation` on `input` or `input.<path>` (for example `input.topic` or `input.tags[1]`; a missing required property is reported on its own key).

```go
_, err := client.Agents.Invoke(ctx, "triage", garrison.InvokeRequest{Input: `{"count":2}`, InputContentType: "application/json"})
var apiErr *garrison.Error
if errors.As(err, &apiErr) && apiErr.FieldCodes["input.topic"] == garrison.FieldCodeInputSchemaViolation {
	fmt.Println(apiErr.Fields["input.topic"])
}
```

`Agent` has `InputMode`, `InputSchema`, and `OutputSchema`; `InvokeRequest` has `InputContentType`. Validation errors about the schemas use the field keys `inputSchema` and `outputSchema`.

```go
schema := json.RawMessage(`{"type":"object","properties":{"topic":{"type":"string"}},"required":["topic"]}`)
err := client.Agents.Create(ctx, garrison.Agent{Name: "triage", InputMode: "Structured", InputSchema: schema}, &agent)
```

## JSON-valued fields

Fields that hold JSON are real JSON values on the wire, and the SDK types them as `json.RawMessage` (with `omitempty`) so they round-trip exactly. Unmarshal one into your own type when you need its contents.

| Type | Field | Value |
|---|---|---|
| `Agent`, `AgentRevision`, `CapabilityDescriptor` | `InputSchema`, `OutputSchema` | JSON Schema document, usually an object; nil when none |
| `Run`, `FanOutMember` | `StructuredOutput` | any JSON value; nil when there is none |
| `RunEvent` | `RawEvent` | the harness output line as a JSON object; `RawEventText` (`*string`) carries it instead when the line is not valid JSON |
| `RunEvent`, `TranscriptEntry` | `ToolInput` | a `ToolCall`'s arguments when they are JSON; `Text` is then omitted |
| `RunEvent`, `TranscriptEntry` | `ToolOutput` | a `ToolResult`'s output when it is a JSON object or array; `Text` is then omitted |
| `Approval`, `TranscriptApproval` | `Input` | the input as a JSON object; otherwise `InputPreview` holds it as text, and only one of the two is set |
| `NotificationDelivery` | `Payload` | the notification body as a JSON object |
| `McpToolDetail` (in `McpServerTestResult.ToolDetails`) | `InputSchema` | the tool's JSON Schema |
| `AgentRevisionChange` | `From`, `To` | an object for the `inputSchema` and `outputSchema` fields, a JSON string for the others |

```go
var out struct {
	Verdict string `json:"verdict"`
}
if len(run.StructuredOutput) > 0 {
	err = json.Unmarshal(run.StructuredOutput, &out)
}
```

## Warnings

A few numeric fields have a documented range, and the server clamps an out-of-range value to the nearest allowed value instead of rejecting the request. The create and update responses for agents, deployments, harness profiles, MCP servers, and workspace templates then carry a `warnings` array of `FieldWarning`: `Field` (the REST field name, for example `maxAttempts` or `delegationMaxDepth`), `Code` (`FieldWarningValueClamped`), `Given` and `Stored` (the values as text, `*string`), and `Message`. The array is omitted when there is nothing to report and on reads, and the server never stores it. `Agent`, `Deployment`, `HarnessProfile`, `WorkspaceTemplate`, and `ManifestApplyItem` have a `Warnings []FieldWarning` field; for MCP servers, decode into your own struct with a ``Warnings []garrison.FieldWarning `json:"warnings"` `` field or into a `map[string]any`.

```go
var dep garrison.Deployment
body := map[string]any{"name": "helper", "agentId": agentID, "harnessProfileId": profileID, "maxAttempts": 99}
if err := client.Deployments.Create(ctx, body, &dep); err != nil {
	return err
}
for _, w := range dep.Warnings {
	fmt.Println(w.Field, w.Code, w.Message) // maxAttempts ValueClamped ... 10 was stored.
}
```

See "Warnings" in `REST_API.md`.

## Model prices

`client.ModelPrices` provides tenant-scoped list, get, create, update, and delete operations for `/model-prices`. ## Usage quotas

The usage-quota module provides CRUD operations and `client.UsageQuotas.Usage(ctx, id)` for current daily UTC meters. Scope an entry to Tenant, Agent, or Deployment; null limits are unlimited and zero disallows usage. Limits cover admissions, completed tokens/cost, and active concurrency. Unknown cost keeps admission open and sets `costAccountingComplete=false`. Refusals carry `QuotaExceeded` and name the limit. Only administrators have built-in write grants. See [REST API](../../REST_API.md#usage-quotas) for accounting boundaries and supported CLI budget enforcement.

Usage quotas default to monitoring only. Explicitly set `enforcementEnabled` to `true` (Go: `EnforcementEnabled`, C#: `EnforcementEnabled`) on an active quota to enforce limits. Disabled enforcement does not reject runs or lower harness budgets.

## App gateway client

`AppGatewayClient` is for an app's end users. ## Executor capabilities

Deployments accept `requiredCapabilities`: `isolation` (`Process`, `Container`, `SandboxedRuntime`), `egressControl`, `filesystemSnapshot`, `sessionContinuation`, `crossNodeRestore`, and optional required `coldStartClass` (`Immediate`, `Cold`, `Warm`). Defaults add no requirement beyond Process. Runs retain an admission-time copy. Workers expose `executorCapabilities`; legacy executor names promise no advanced capabilities. Set `executor: "KubernetesJob"` with Container requirements. Unsupported requirements remain queued with `NoCapableWorker`.

Kubernetes workers can report `warmStart: true` alongside `coldStartClass: "Cold"`; this satisfies either Cold or Warm requirements. Warm support requires enabled warming and Kubernetes RBAC. Explicit Warm requirements reject PersistentVolume workspaces and custom pod resources.

## Trust level

`Deployment.TrustLevel` is `TrustLevelTrusted` (the default when empty) or `TrustLevelUntrusted`. Untrusted runs need at least Container isolation on top of `RequiredCapabilities`: an unset `Executor` resolves to `KubernetesJob`, `Process` is rejected with field code `UntrustedNeedsIsolation`, and a run no Ready worker can isolate stays `Queued` with `BlockedReason` `"NoIsolatingWorker"`. `Run.TrustLevel` reports the admitted level. A tenant with `requireUntrustedDeployments` (set through `client.Tenants`) rejects Trusted deployments with field code `TenantRequiresUntrusted`. See "Deployment trust level" in `REST_API.md`.

## Egress allowlist

`Deployment.EgressRules` (`[]DeploymentEgressRule`) is the deployment's egress allowlist. Each rule has `CIDR` (required, for example `"203.0.113.0/24"`), `Port` (`*int`, 1 to 65535, nil for every port), and `Protocol` (`EgressProtocolTCP`, the default when empty, or `EgressProtocolUDP`). An empty list keeps the cluster's default run egress. With rules, a run pod may reach only DNS, the Garrison server MCP port, and the listed rules; host names are not accepted, so resolve them to CIDR blocks first. Validation errors are 400 field codes: `TooManyEgressRules` (more than 64 rules), `InvalidCidr` (not a CIDR network address, for example a host name or `203.0.113.7/24` with host bits set), `PortOutOfRange`, `InvalidProtocol`, `EgressRulesNeedKubernetesJob` (`executor` `Process` with rules), and `EgressRulesNeedColdStart` (`coldStartClass` `Warm` with rules). With rules, every run needs egress control and at least Container isolation: an unset executor resolves to `KubernetesJob`, and a run no Ready worker can enforce the allowlist for stays `Queued` with blocked reason `NoIsolatingWorker`; it is never run unenforced. See "Egress allowlists" in `docs/SECURITY.md`.

## Effect policy

`Deployment.EffectPolicy` is `EffectPolicyAtMostOnce` (the default when empty on create), `EffectPolicyAtLeastOnce`, or `EffectPolicyJournaled`. It decides what happens to a run that was already `Running` when its worker was lost: `AtMostOnce` ends it `Failed` with outcome `NodeLost`, `AtLeastOnce` requeues it while `MaxAttempts` allows, and `Journaled` behaves as `AtMostOnce` until the effect journal exists. A run that was still `Leased` never started, so it is requeued under every policy. `Run.EffectPolicy` reports the policy the run was admitted under; changing the deployment later does not change how that run is handled. The server still accepts the deprecated `retryOnNodeLoss` in a map body (`true` is `AtLeastOnce`, `false` is `AtMostOnce`) and rejects one that disagrees with `effectPolicy` with a 400 field error on `effectPolicy` (code `EffectPolicyConflict`); the `Deployment` struct does not carry it, so updates through the struct never conflict. See "Effect policy" in `REST_API.md`.

### Management MCP clients

The same agent/deployment/manifest validation, default bindings, versioning, and audit behavior now serve REST and management MCP. Use normal developer/user credentials for MCP configuration tools; hosted run tokens cannot change configuration. Existing SDK REST methods are unchanged. See [management MCP tools](../../docs/MANAGEMENT_MCP.md) for the MCP contract and replacement semantics.


Effect safety and continuation: run operations expose gateway intent metadata (no raw arguments or secrets). `Suspended` is an active status, so completion waits keep polling until a terminal status. Suspension and resume occur automatically for deployments with `suspensionEnabled` and compatible pinned harness `sessionFormat`; there are no manual suspend/resume endpoints. A raw CLI attempt lost after resuming fails closed if its new epoch lacks a safe checkpoint.

Remote agents use kind `Remote`, protocol `A2A` or `Mcp`, a full `remoteEndpointUrl`, and optionally `remoteCredentialSecretId` and `registrationTtlSeconds`; `mcpToolName` selects the remote MCP tool. Executors include `RemoteA2A` and `RemoteMcp`. See [remote agents](../../docs/REMOTE_AGENTS.md) and [tenant scheduling](../../docs/TENANT_SCHEDULING.md). Queue saturation returns HTTP 429 with code `QueueFull`, rather than creating a failed run.

System administrators can change tenant `schedulingWeight` (1 to 1000, default 1), use server settings for credential/run-token expiry policies and queue bounds, and run the master-key rotation method. Rotation uses keys already configured on the server and returns counts only; clients never supply key material to the endpoint. Keep old keys until a pass reports zero conflicts and failures.

LeaseBroker secret metadata uses `kind: "LeaseBroker"`, `brokerResource`, and optional `brokerAudience`; it rejects a static `value`. Issuance/revocation endpoints and provider authorization are operator-only settings. See the [provider contract](../../docs/CREDENTIAL_BROKER.md) for TTL, tombstone, and tenant authorization requirements.

`client.Runs.Placement(ctx, runID)` returns read-only placement diagnostics. `client.Runs.DatabaseUsage(ctx, runID)` returns exact SQL attempts inside completed instrumented lifecycle scopes. Placement eligibility is advisory and reserves no capacity. External invocation wait is best effort: when the server wait budget is full, it returns the accepted run for polling. Resident synchronous delegation instead fails with `DelegationCapacityExhausted` before child creation when no wait slot is available. Poll an accepted run's ID instead of submitting another invocation.
