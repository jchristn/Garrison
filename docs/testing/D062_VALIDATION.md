## Implemented behavior

- Application operation metrics and nested traces cover gateway fencing/journal stages, credential broker calls, run lifecycle, workspace preparation, git cache work, checkpoint capture/restore/transfer and agent memory. Dimensions are fixed component/operation/outcome values, not keys, paths, credentials or user text.
- Migration 34 stores actual ADO statement attempts attributed to completed run-operation scopes, independently of unrelated concurrent database work. The tenant run `database-usage` endpoint and four SDKs expose these counters. Statement errors/retries and explicit transaction wrappers are counted; attribution persistence excludes itself. A process crash before the best-effort scope flush can lose that scope's counters, so these are observed completed scopes, not a crash-proof accounting ledger.
- Tenant run `placement` explains current global/node eligibility using shared scheduling predicates, including capability, selectors, isolation, dedication, affinity, concurrency and applicable quotas. It does not lease or reserve a slot; concurrent changes can alter the next actual claim. Other tenants' dedicated node inventory is omitted.
- `Scheduling.MaxSynchronousWaiters` bounds held invocation and pipeline waits per replica, default 256 and range 1 to 768. Excess wait requests return the accepted run for polling, preserving worker request headroom. REST invocation returns 202 for a nonterminal run; pipeline creation retains its existing 201 contract. The cap covers both types of wait together. A resident non-durable parent reserves a slot before the child handshake or creation and receives `DelegationCapacityExhausted` when full. An admitted child wait retains its reserve eligibility until the wait ends; `delegation_denied` is distinct from accepted external fallback in admission metrics.
- `IAgentMemoryStore` separates protocol/authorization from storage. The optional `FilesystemAgentMemoryStore` persists tenant/agent/key-scoped text with atomic replacement, UTF-8 byte bounds and owner-only files. Three MCP tools expose read/write/delete. Hosted runs are restricted to their own agent; user/developer calls require Agent.Execute. NotDory is an optional external MCP example rather than a mandatory backend. See [AGENT_MEMORY.md](../AGENT_MEMORY.md).
