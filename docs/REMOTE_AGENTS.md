# Remote agent execution

A remote registration is an agent whose `kind` is `Remote`, with `remoteProtocol` set to `A2A` or `Mcp` and an absolute HTTP(S) `remoteEndpointUrl`. Invoke it through the ordinary agent invoke API, MCP delegation, or the A2A gateway. A worker performs the outbound call and reports its result through the existing fenced node protocol. No hosted deployment or harness installation is needed; omit `deploymentId` and conversation options.

Use `POST /v1.0/api/tenants/{tenantId}/agents/register` to create or renew a registration by name. A positive `registrationTtlSeconds` expires relative to `lastRegisteredUtc`, which registration sets on the server. Zero disables expiry. An expired registration remains visible for diagnosis, but new admission returns `RemoteRegistrationExpired`. The compiler checks it again when the run is claimed. The worker checks before protocol setup and again immediately before the mutating A2A message or MCP tools/call, so a slow health check cannot extend registration validity. Renew by registering again. Inactive agents cannot be invoked; registration and configuration updates honor the submitted active flag.

For A2A, point the URL at the peer's JSON-RPC endpoint. Its agent card must be served at the endpoint followed by `/.well-known/agent-card.json`. Before sending input, the worker fetches that card as a health check. It sends a blocking `SendMessage` with the Garrison run ID as the message ID, and polls any returned working task. Completed task artifact text, direct message text, or task status text becomes the result. A task requiring additional input or authentication fails the invocation; remote peers are not harness conversations.

For MCP, point the URL at the Streamable HTTP endpoint, including its path. Set `mcpToolName` to the remote tool's name. If you also expose this registration as a Garrison MCP tool, its name must obey Garrison's reserved-prefix rule. Otherwise remote tool names may include `garrison_`. Supply a JSON object as input: its fields are the tool arguments. The worker initializes the endpoint and checks `tools/list` before dispatching `tools/call`. Text content becomes result text; `structuredContent` is retained as structured output. `isError` fails the run. Stdio and legacy SSE remote endpoints are not supported.

`remoteCredentialSecretId` optionally identifies a bearer-token secret in the registration's tenant. It can also reference a configured LeaseBroker secret; issuance/revocation then follows the [credential broker](CREDENTIAL_BROKER.md) contract. The compiler resolves it at claim time and includes it only in the worker lease contract. It is sent as an Authorization header, and result/error text is scrubbed against its value. A secret in another tenant cannot be read. Treat worker lease responses as sensitive.

Workers advertise the `RemoteA2A` and `RemoteMcp` executors. Existing workers without those capabilities do not claim remote runs. A remote run has a logical `deploymentId` equal to its agent ID for run accounting; it does not create a deployment record. Tenant and agent quotas apply. Deployment configuration, workspace preparation, local artifacts, and harness session continuation do not apply.

Both transports use the shared outbound address guard: metadata, link-local, unspecified, multicast, and reserved destinations are blocked when the connection is opened, including after DNS resolution. Redirects and HTTP proxies are disabled. Private and loopback addresses are allowed for cluster services. Call deadlines and cancellation bound the local request; when an A2A task ID is known the worker also attempts a bounded remote cancellation. A remote peer may already have performed an effect. Transport failures are never automatically replayed, and remote runs use `AtMostOnce` with one attempt.

The worker emits `RemoteHealthy` before dispatch after a successful protocol health check. A health failure fails the run without dispatching input. This is a dispatch-time check, not a periodic availability promise.


Admission does not reserve the remote peer or establish exactly-once external execution. The final expiry check prevents a new dispatch after TTL expiry but cannot recall a request already sent. Cancellation is best effort at the peer. A2A input-required/auth-required responses are explicit failed remote invocations, not local durable session checkpoints. Filesystem snapshot/cross-node restoration capabilities belong to the compatible Process executor, not these transports.

Run placement diagnostics use the same stored remote executor requirements as claim selection. They can explain registration expiry, worker capabilities and current capacity without invoking the remote endpoint or reserving a worker. Remote endpoint health is established at actual worker dispatch, not by that read-only diagnostic.
