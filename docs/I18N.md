# Internationalization

The Garrison dashboard is translated end to end, and so is the end-user app UI in `app-ui/`, which ships the same locale set with its own catalogs ([APP_UI.md](APP_UI.md#languages)). Every visible string, tooltip, placeholder, `aria-label`, toast, error message, and empty state comes from a translation catalog. Dates, numbers, durations, currency, byte sizes, and lists are formatted with `Intl` for the active locale.

The locale set matches Armada (D-017). The registry lives in `dashboard/src/i18n/localeRegistry.js`. It maps aliases case-insensitively (`de-AT`, `fr-CA`, `es-419`, `zh`, `zh-CN`, `zh-TW`, `zh-HK`, `yue`, `pseudo`, `rtl`) to canonical codes, drops subtags from the end until something matches (`es-AR` becomes `es`), and tells `Intl` which locale to use. `zz` formats with `ar` so numerals and dates also render right to left.

### Supported locales

Every locale in the registry is complete and supported: the key parity tests fail on any missing key, and the dashboard and the app UI list the same locales by their own names, with no beta marker. The review checklist below still applies to every catalog change.

### Native-speaker review checklist

Reviewers work through the dashboard in the target language (`?lang=<code>`) and the catalog files side by side.

1. Terminology: every Glossary term below is used, and used the same way on every page and in every tooltip. Flag glossary choices that read unnaturally to practitioners in your region.
2. Register: one form of address throughout (tú, vous, tu, 你), no mixed formality.
3. Meaning: tooltips explain what the control does and how to use it, with the same detail as English. Nothing is shortened to the label.
4. Grammar in generated titles: the nine `rp(...)` strings per record page (add, create, edit, view, delete, empty state) agree in gender and number.
5. Plurals: counts read correctly for 0, 1, 2, and large numbers (`_one`, `_other`, and `_many` for es, fr, and it).
6. Placeholders: `{{name}}` values land in a natural position; nothing reads as a fragment.
7. Untranslated text: only product names, protocol names, API paths, field names, and literal values stay in English.
8. Punctuation and typography: no em-dashes or en-dashes; French non-breaking spaces and « »; full-width CJK punctuation and the right quote marks; a space between Han characters and Latin words.
9. Cantonese only: sentences are written Cantonese (係, 喺, 嘅, 唔, 冇, 咗), not Mandarin in Traditional characters, with Hong Kong vocabulary.
10. Layout: check Home, Runs, a create form, Settings, and the setup wizard at 1280, 768, and 390 px for truncation and overflow.
11. Formatting: dates, times, numbers, currency, durations, and relative times look right for your region.
12. Fonts: CJK text renders with the regional glyph shapes (Simplified, Taiwan, or Hong Kong).
13. Record the review (reviewer, date, catalog revision) in the pull request.

## How the active locale is chosen

1. The `?lang=` query string (handy for screenshots and bug reports).
2. The saved choice in `localStorage` under `garrison.locale`.
3. The browser language.
4. English.

Changing the language from the top bar or the login page saves the choice and updates `<html lang>` and `<html dir>` immediately. No reload is needed.

## Rules for contributors

- Never write user-facing text in JSX or JavaScript. Add a key to `en.js`, then add the same key to every other catalog (`de`, `ja`, `es`, `fr`, `it`, `zh-Hans`, `zh-Hant`, `yue-Hant`).
- Use interpolation (`{{name}}`) instead of string concatenation, because word order differs between languages.
- Use i18next plurals for counts: add `key_one` and `key_other` in English. Spanish, French, and Italian also carry `key_many` (same text as `key_other`), because `Intl.PluralRules` uses that category for large numbers. Japanese and Chinese use the same text for every form.
- Never use em-dashes in any catalog. Restructure the sentence instead.
- Give every new control a `tips.*` entry and attach it with `tip(text)` from `components/Tooltip.jsx` (or the `tip` prop that tables, form fields, badges, and KPI cards accept). Never use the native `title` attribute. A tooltip says what the control does and how to use it; it never just repeats the label.
- Format values with the helpers in `formatters.js`, passing `i18n.language`. Do not call `toLocaleString()` without a locale or build dates by hand.
- Use CSS logical properties and flex or grid layouts so RTL works without special cases. The RTL audit fails on physical `left`/`right` properties.
- Leave room for German, which runs about 30% longer than English. Check the `zz` locale at 390 px wide.

## Tests

`npm test` runs `src/tests/i18nKeys.test.jsx`, which fails when:

- a static `t('...')` key in the source does not exist in English;
- a key generated by a resource configuration (columns, fields, filters, steps, row actions) does not exist in English;
- a route is missing its navigation label or tooltip;
- an enum value has no label;
- a registered locale has no catalog, or a catalog has no registry entry;
- any translated locale has a key English lacks, or lacks a key English has (plural suffixes are compared by base key);
- a translation drops or renames an interpolation placeholder;
- a translation has an empty or non-string value;
- a translation is still identical to English, unless it is made only of product terms or is on the per-locale list in `src/tests/untranslatedAllowlist.js`;
- an acronym (MCP, API, URL, JSON, and so on) is written in lower case in any catalog;
- any catalog contains an em-dash or en-dash;
- the pseudo-locale is incomplete or loses placeholders.

`src/tests/i18n.test.js` covers the registry (aliases, direction, `Intl` locale, labels, font hints), switching (`lang`, `dir`, `--locale-font`, persistence) for every locale, and the formatters with explicit locales: dates, numbers, currency, percentages, relative time, durations, and lists in `es`, `fr`, `it`, `zh-Hans`, `zh-Hant`, and `yue-Hant`.

`src/tests/tooltips.test.jsx` resolves the English tooltip for every column, field, list-editor item, form section and step, row action, filter, add button, hub, tab, status badge, analytics chart and metric, and run telemetry field, and fails when one is missing, shorter than 25 characters, or only restates its label.

`tests/e2e/tooltips.spec.js` signs in against mocked APIs, visits every route and tab, opens every create and edit form step, row action menus, the column picker, record modals, the setup wizard, and the tour, and fails when any visible button, link, input, select, textarea, table header, tab, label, or KPI card lacks a tooltip or has one that only repeats its visible text.

`tests/e2e/i18n.spec.js` checks that the login and top-bar selectors list every locale by its own name with no beta label; switches to each translated locale, checks `lang`, `dir`, translated text, and persistence across a reload, then visits every route and fails if visible text or a `data-tip`, `aria-label`, `placeholder`, or `title` attribute contains a raw key such as `views.home.title`. It also runs the RTL audit described below. `tests/e2e/dashboard.spec.js` switches to German and to `zz`.

## Adding a locale

1. Add an entry to `LOCALES` in `localeRegistry.js`: code, English name, native name (autonym), direction, and aliases. Add `intl` if browsers format the code poorly, and `fontFamily` for scripts that need a regional font.
2. Create `src/i18n/locales/<code>.js` and `<code>.tips.js` with a full copy of the English keys, translated. Follow the Glossary; add a column for the new language first.
3. Import the catalog in `resources.js` and add it to `TRANSLATIONS`.
4. Add the locale to `UNTRANSLATED_ALLOWLIST` in `src/tests/untranslatedAllowlist.js` (start empty) and to the expectations in `src/tests/i18n.test.js`.
5. Run `npm test`, then `npx playwright test tests/e2e/i18n.spec.js`, then check every page in the new locale at 1280, 768, and 390 px.

## Right-to-left languages

The dashboard is RTL-ready (P5.49). Adding Arabic, Hebrew, Persian, or Urdu needs no code or stylesheet changes:

1. Add the registry entry with `dir: 'rtl'`, for example `{ code: 'ar', englishName: 'Arabic', nativeName: 'العربية', dir: 'rtl', aliases: ['ar-sa', 'ar-eg'] }`. Add `fontFamily` if the default system stack renders the script poorly.
2. Add the catalog files and register them as in "Adding a locale".

`index.js` sets `<html dir>` from the registry, and everything else follows from it:

- Layout uses logical properties only: `margin-inline`, `padding-inline`, `inset-inline`, `border-inline`, and `text-align: start` or `end`. The sidebar, its divider, the mobile drawer, tables, forms, toasts, the password reveal button, code-block toolbars, and timeline accents all flip automatically.
- Directional icons carry the `icon-mirror` class (pagination chevrons, send, log out) and the relationship arrows use `.relation-arrow`; both flip with `transform: scaleX(-1)` under `[dir='rtl']`. Icons that are not directional (refresh, copy, trash) never mirror.
- Portaled popups (row action menus, the export menu, the column picker, the tour card) are placed in viewport coordinates, so `src/utils/direction.js` resolves which edge of the trigger to align with. Tooltips and chart hover cards center on, or follow, the pointer and are clamped to the viewport.
- Charts keep a left-to-right time axis in every locale (`.chart-canvas svg { direction: ltr }`), which is the common convention in RTL dashboards and keeps SVG `text-anchor` stable. Legends and chart headers follow the page direction.
- Identifiers, code, and JSON (`code`, `pre`, `.cell-id`) stay left to right inside RTL text; textareas use `unicode-bidi: plaintext` so each paragraph takes the direction of its own text.

The RTL audit in `tests/e2e/i18n.spec.js` keeps this true. It visits every route in `zz` at 1280 and 390 px and in English with `dir="rtl"` forced, and fails on horizontal page overflow; it scans every stylesheet rule and inline style for physical `left`/`right` properties (margin, padding, border, inset, float, and `text-align: left|right`) outside a short allowlist of viewport-positioned popups; and it checks that the sidebar sits on the right, that chevrons mirror, that the row action menu stays inside the viewport aligned to its trigger, and that chart SVGs stay LTR. Use logical properties in new CSS, and give new directional icons the `icon-mirror` class.

Register and punctuation:

- Spanish and Italian address the operator with the informal "tú" and "tu"; French uses "vous". Chinese and Cantonese use 你.
- French puts a non-breaking space (U+00A0) before `:`, `;`, `?`, and `!`, and quotes with « ».
- Chinese and Cantonese use full-width punctuation (，。：；？！（）). Simplified Chinese quotes with “ ”, Traditional and Cantonese with 「」. Put a half-width space between Han characters and Latin words, numbers, or placeholders (`MCP 服务器`, `{{count}} 个`).
- Cantonese (`yue-Hant`) is written Cantonese, not Mandarin in Traditional characters: full sentences use 係, 喺, 嘅, 唔, 冇, 咗, 啲, 佢, 嚟, 畀, 睇, 揀, 撳, 點樣. Short labels and buttons may use standard Hong Kong written forms (儲存, 取消, 刪除).
- No em-dash (U+2014, including the doubled Chinese form) and no en-dash (U+2013) anywhere. Use a colon, comma, parentheses, or two sentences.
